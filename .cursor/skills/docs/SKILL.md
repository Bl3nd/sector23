# Component Docs

A component should have a docs page that both showcases and explains it.

## Who this documentation is for

Sector23 component documentation is for a user that wants to learn more about Sector23 or who already uses the components. It should provide insight into how to use the component and its related behavior through its available props. Therefore, explainations or prose should be concise and to the point without including unnecessary and inessential information to what is being described.

## Title and description

The documentation page should have the title of the component, example: `Accordion`. It should also have a description that is an overview of what the component is in one sentence.

## Base UI

With Base UI having extensive documentation for their components, we should not re-explain its behavior unless we changed it. Additionally, if a demo does not showcase a different behavior that requires a style change, we do not need to showcase it. If it is not explained in Base UI's components documentation, add the explaination. If a demo is not already created, create it and explicitly state that you did within the response.

## Duplication

Our docs should not duplicate any documentation that Base UI already provides, other than the prescribed showcasing in the above `Base UI` section.

## Scope

The component documentation should be specific to the component unless there are related components that are essential to include when warranted.

## External links

When linking to Base UI, make sure the link actually works and sends the user to the correct section.
